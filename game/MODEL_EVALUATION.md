## 5 November 2026: observed third-person wrapper

An isolated, authenticated Qwen2.5 1.5B CPU server answered the captured synthetic Niko dragon follow-up with `Niko chuckles,` followed by a wholly quoted reply. The existing adapter passed that third-person introduction through as character speech. It now removes this narrowly identified speaker/action wrapper when the following quotation is complete, retaining the model’s words; incomplete or unquoted narration uses the existing written fallback. A regression test replays the observed response and checks incomplete and ordinary reported dialogue. A separate Ministral test produced a distinct third-person wrapper: a paragraph beginning “Mira’s fingers trembled” and describing her voice, followed by a complete italicized quotation. The adapter now also recognizes a tightly bounded family of current-speaker possessive action-and-voice paragraphs followed by one wholly quoted reply, retaining the exact spoken words. Incomplete quotations, other-character narration and ordinary reported dialogue are tested separately. Neither formatting correction establishes factual grounding or fixes every form of narration.

A separate paired probe changed prior private-turn labels from `Player to Niko` to `Player` for two captured follow-ups and three requested seeds. The changed labels led to some more direct replies but also introduced an unsupported recurring return; rerunning one requested seed produced a different baseline answer. These stochastic samples are not sufficient to justify changing the production prompt. No player data was used; the model server was stopped.

## 5 November 2026: context-window failure and recovery

A synthetic request through the real dialogue adapter used a 1,654-character English scene, four long Japanese history entries and a 500-character Japanese message. An isolated CPU Qwen2.5 7B llama.cpp server configured with a 2,048-token window returned HTTP 400: it counted the prompt as 2,921 tokens and identified `exceed_context_size_error`. Previously the game showed only a generic request failure. The adapter now recognizes that exact structured error, retains the written fallback and explains that the player can increase the context size or choose a model with a larger window. It does not discard story context or expose the provider's response. Other errors retain their prior generic or specific handling. The example uses repetitive synthetic text and a constructed scene, not a real conversation, browser, or physical device; it does not establish how often this happens or the capacity of other providers. The English scene and Japanese history are a deliberately token-heavy test, and token counts vary with the model and server.

To repeat, start a local OpenAI-compatible llama.cpp server configured with the desired context window, then run `node tests/context-window-model-eval.mjs http://127.0.0.1:PORT/v1/chat/completions MODEL_ID`. The probe allows literal loopback addresses only and sends no player data. The temporary server was stopped after testing.

## Two-pass factual extraction experiment

We also tested whether asking the local model to extract relevant facts before composing a character's reply would improve continuity. Using the current adapter prompt and synthetic scenes, we compared the normal single reply with an extra extraction call whose answer was included in the dialogue prompt. Qwen2.5 Instruct 7B Q4 ran on CPU with six threads, a 4,096-token context and seeds 1 and 42. There were four prompts per seed: an earlier choice involving a lid, a companion's current location, the character's relationship to the person who taught him repairs, and a request for a funny machine nickname. The experiment used no player data; `node tests/two-pass-grounding-model-eval.mjs LOCAL_ENDPOINT MODEL_ID` repeats it against a local OpenAI-compatible server.

The extra pass did not establish reliable grounding. For the lid, both extracted summaries described the player's completed choice as a suggestion, and both generated replies introduced unsupported details rather than recalling that the player wore it. For the location question, the extractor correctly identified that Mira was downstairs in both runs, but one subsequent reply instead asserted an unsupported back-room destination. The character also invented his brother's name in one of the two enhanced replies, compared with both baseline replies. All four nickname replies were playful. These are small samples and the observations do not establish a general error rate; the experiment shows that this approach can still introduce or preserve errors even when extraction succeeds. The two-pass replies took approximately 5.6–15.2 seconds versus 3.0–8.8 seconds for the baseline on this machine, and require twice as many requests. We did not add the extra pass to the game.

## Mallow's audit reflection: witnessed context probe

A synthetic comparison tested two questions after the audit: whether Mallow can see the catch when the lens is covered, and whether the printer is working after the player unplugs it. Each baseline used the authored reflection context; its paired candidate added the short witnessed context for that audit action. Qwen2.5 Instruct 7B Q4_K_M ran locally on a llama.cpp CPU server with four threads, a 4,096-token context, temperature 0.8 and the adapter's 100-token limit.
